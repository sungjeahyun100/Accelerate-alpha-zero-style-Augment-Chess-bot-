# 증강체스 규칙 요약

> 알파제로 팀이 규칙을 잘못 이해해서 생기는 버그를 줄이기 위한 문서입니다. 사이트(augmentchess.org)와 `infra/engine-merged.js`의 JS oracle을 현재 규칙 기준으로 삼고, 향후 Rust 엔진은 differential test로 이 동작과의 동등성을 검증합니다.

## 1. 문서의 범위와 판정 우선순위

증강체스는 카드, 특수 기물, 필드 규칙이 서로 조합되므로 모든 경우의 수를 자연어 문서 하나에 나열하기 어렵습니다. 규칙이 충돌하거나 이 문서가 코드와 다를 때는 다음 순서로 판정합니다.

1. 현재 augmentchess.org의 실제 동작
2. `infra/engine-merged.js`의 `generateActions()`가 만든 행동과 `applyAction()`이 적용한 결과
3. 이 문서의 요약

이 문서는 구현자의 입문서이지 독립적인 새 규칙 정의가 아닙니다. 사이트 패치로 동작이 바뀌면 oracle과 이 문서를 함께 갱신합니다.

## 2. 핵심 규칙

- 기본 보드는 8×8이고 백이 먼저 둔다.
- 폰, 나이트, 비숍, 룩, 퀸, 킹의 기본 행마와 캐슬링, 앙파상, 폰 승격을 지원한다. 단, 활성화된 카드와 필드 규칙이 이를 변경할 수 있다.
- 행동은 크게 `move`, `card`, `promotion`, 특수 기물 행동으로 나뉘다.
- 보통의 기물 이동은 행동 횟수를 소모하고, 기본 상태에서는 상대에게 턴을 넘긴다.
- 카드 사용은 일반적으로 턴을 넘기지 않는 무료 행동이다. 카드 사용 후에도 동일 플레이어가 기물을 움직일 수 있다.
- `acceleration` 규칙이 활성화되면 기본 행동 한도가 1에서 2로 늘어난다. 추가 이동, 턴 건너뛰기, 강제 연속 이동은 또 다른 예외를 만든다.
- 카드나 특수 기물이 만든 강제 추가 이동이 있으면 다른 기물을 선택할 수 없을 수 있다. 일부는 `skip` 행동으로 포기할 수 있지만 필수 연속 이동은 그렇지 않다.

### 좌표와 방향

oracle의 보드 좌표는 `board[row][col]`이다. `row = 0`이 흑의 홈 랭크, `row = 7`이 백의 홈 랭크이며 백 폰은 행 번호가 줄어드는 방향, 흑 폰은 늘어나는 방향으로 전진한다.

## 3. 승패와 종료

### 기본 승리 조건

이 엔진의 기본 모델은 정통 체스의 체크메이트가 아니라 **상대 왕족(royal/critical) 기물의 실제 제거**다.

- 일반적으로 상대 킹을 잡으면 즉시 승리한다.
- `royalKnight`, `shotgunKing`, `darkWizard`, `vip`, `merchant`, `timeTraveler`, `vampireLord`, `crownRoyal` 표식 기물 등도 국면에 따라 승패를 결정하는 왕족이 될 수 있다.
- 폭발, 장판 붕괴, 카드의 일괄 제거 같은 간접 효과로 양쪽 왕족이 동시에 사라지면 무승부가 될 수 있다.
- `regency` 효과가 있으면 킹이 제거된 뒤 퀸이 왕위를 이어받을 수 있어, 킹 제거가 즉시 패배가 아닐 수 있다.
- `democracy`와 같은 규칙은 왕 대신 폰 집단을 생존 조건으로 바꾸기도 한다.

따라서 포팅 시 `체크 중인 왕은 반드시 피해야 한다`, `자신의 왕을 체크에 노출하는 수는 항상 불법이다`, `합법수가 없으면 체크메이트/스테일메이트다`라는 정통 체스의 가정을 임의로 넣으면 안 된다. 합법 행동은 oracle의 수 생성 결과를 기준으로 한다.

### 카드·필드 규칙의 추가 승리 조건

| 효과 | 종료 개요 |
|---|---|
| `captureTheFlag` | 상대의 홈 랭크에 있는 깃발 칸을 점령하고 지정된 기간을 버티면 상대가 패배한다. |
| `racingKing` / `machoChess` | 왕 역할의 기물이 목표 랭크에 도달하면 승리한다. |
| `religiousVictory` | 해당 색의 비숍이 상대보다 3개 이상 많으면 승리한다. |
| `binaMate` | 상대 왕족을 두 기물이 동시에 공격하는 조건으로 승리할 수 있다. |
| `highlander` | 아군에 남은 각 기물의 종류가 모두 다르면 승리한다. |
| `democracy` | 해당 색의 모든 폰이 제거되면 패배한다. |
| `crownRule`, `prophecy`, `ultimatum`, `herald` 관련 효과 | 거점 점유, 카운트다운, 목표 미이행, 왕족 위협 등 각 효과의 전용 조건으로 승패를 판정한다. |

위 표는 대표 목록이며, 카드 설명과 oracle의 상태 전이가 구체적인 카운트와 예외를 결정한다.

### 무승부 규칙

`infra/engine-merged.js`는 일반적인 스테일메이트, 3회 반복, 50수 무승부를 자체적으로 종료 판정하지 않는다. 카드 효과나 동시 제거가 `winner = "draw"`를 만드는 경우만 엔진 자체의 무승부다.

기존 `infra/selfplay-worker-merged.js`는 학습 대국이 무한히 지속되는 것을 막기 위해 별도로 다음을 적용한다.

- 턴이 실제로 넘어간 시점의 동일 보드+턴이 3회 반복되면 무승부
- 잡기나 폰 이동 없이 30 ply가 지나면 무승부. 로그 이름은 `50-move`지만 정통 체스의 50수 규칙과 수치가 같지 않다.
- 최대 ply 한도까지 결과가 없으면 `draw`가 아니라 `unfinished`로 기록

새 Rust 엔진에서는 **사이트 규칙**과 **self-play 조기 종료 정책**을 별개로 모델링해야 한다.

## 4. 턴과 행동 구조

```text
턴 시작 효과 해결
  → 0개 이상의 카드 사용(합법한 조합만)
  → 기물 이동/특수 행동
  → 강제 추가 이동이 있으면 해결
  → 종료 효과와 승패 판정
  → 카운터·임시 상태 갱신
  → 상대 턴
```

이 흐름은 설명용 요약이다. 실제로는 아이돌 앙코르, `resolve` 무료 이동, `timeStop`, `skipTurn`, `acceleration`, 폰 연속 잡기 등이 턴 전환을 바꾸므로 `turn`, `actionsRemaining`, `turnsTaken`, `moveCount`를 각각 보존해야 한다.

| `Action` 종류 | 의미 |
|---|---|
| `move` | 일반 이동, 잡기, 캐슬링, 앙파상, 포털 이동, 교환 등 |
| `card` | 패의 카드와 대상을 지정해 효과를 적용 |
| `promotion` | `recycling` 규칙의 별도 승격 행동. 일반 폰 승격은 `move` 적용 중 처리될 수 있음 |
| `shotgunReload` | 샷건 킹의 탄약 재장전 |
| `wizardSpell` | 위자드의 주문 실행 |
| `fileSurgeSkip` | 허용된 강제/추가 이동 포기 |

## 5. 카드

### 패와 사용 상태

- 카드는 색별 `deckSlots.white` / `deckSlots.black`에 보관된다. 엔진은 주어진 패의 합법 행동을 만들지만, 일반 대국의 드래프트 UI 전체를 스스로 재현하지는 않는다.
- 각 카드는 최소한 `id`, `instanceId`, `effect`, `phase`, `used`, `recovering` 등의 상태를 가질 수 있다.
- `used`, `recovering`, `nextTurnPending` 상태인 카드는 일반적으로 사용할 수 없다.
- 대상이 필요한 카드는 합법한 칸·기물·복수 선택을 `target`으로 받는다. 대상이 없는 즉시/패시브 카드도 있다.
- 카드는 보통 사용 즉시 `used = true`가 되지만, 회수·재사용·혈액 카드 같은 전용 예외가 있다.
- `trolley`, `premove`, `freeMove`는 동일 턴의 다른 특정 카드와 같이 쓸 수 없는 턴 독점 제약을 가진다.

### 시점 분류

| `phase` | 의미 |
|---|---|
| `OPENING` | 초기 배치나 게임 시작 조건을 바꾸는 카드 |
| `MIDDLE` | 중반 드래프트/사용 대상 카드 |
| `END` | 후반 드래프트/사용 대상 카드 |
| `PIECE` | 기물을 새 종류로 변환하거나 특수 기물을 제공하는 카드 |
| `RULE` | 손패가 아니라 전체 게임의 필드 규칙을 정하는 카드 |

`phase`는 항상 단순한 턴 번호 제한을 의미하지 않는다. 드래프트 단계, 게임 모드, `nextTurnPending`, 개별 효과가 함께 사용 가능 시점을 결정한다.

### 효과 유형

- **즉시 효과**: 제거, 변환, 전향, 교환, 소환, 위치 변경. 예: `extinction`, `miracle`, `qxe1`, `summonColossus`.
- **기물 변환**: 아군 기물을 특수 기물로 바꾸며, 변환 직후 잡기 제한이 적용될 수 있다. 예: `paladin`, `octopus`, `clockwork`, `parrot`, `princess`, `hedgehog`.
- **영구 패시브**: 수 생성이나 승리 조건을 계속 변경한다. 예: `majesty`, `overtake`, `vanguard`, `resolve`, `symmetry`, `highlander`.
- **한 턴/기간제 효과**: 카운터가 끝나거나 소유자의 턴이 종료되면 사라진다. 예: `reversal`, `bribe`, `freeze`, `taunt`, `armistice`.
- **예고된 효과**: 다음 턴 또는 몇 half-turn 뒤에 해결된다. 예: `portalGun`, `lobster`, `icbm`, `collapse`.
- **필드 규칙**: 보드 전체의 이동·잡기·승리 규칙을 바꾸며 손패 카드와 다른 경로로 적용된다. 예: 포털, 블랙홀, 컨베이어, 왕관, 깃발 뽑기.

## 6. 특수 기물

특수 기물의 행마는 기물 자체의 기본 이동과 카드·필드 상태의 보정을 합쳐서 결정한다. 아래는 포팅과 테스트 설계에 자주 필요한 대표 행마다.

| 기물 | 기본 행마·특성 |
|---|---|
| `amazon` | 퀸의 선형 이동 + 나이트 도약 |
| `camel` | (3,1) 도약 |
| `alfil` | (2,2) 대각 도약 |
| `ferz` | 대각선 1칸 |
| `man`, `guard`, `reaper` | 킹처럼 주변 8칸. 잡기 가능 여부는 각 기물의 추가 능력을 따른다. |
| `knightmaster` | 대각선 1칸 도약 |
| `paladin` | 나이트 행마. 일반 기물 잡기에 제약이 있다. |
| `octopus` | 주변 8칸으로 도약. 인접한 적이 없으면 잠수 상태가 될 수 있다. |
| `clockwork` | 퀸처럼 선형 이동. 인접 아군 조건이 행마에 영향을 준다. |
| `parrot` | 같은 색이 직전에 기억한 기물 유형의 행마를 따른다. 기억이 없으면 수가 없을 수 있다. |
| `thief` | 직선 방향 최대 3칸 도약. 중간 기물, 방문 칸, 직전 방향 등의 상태 제약을 받는다. |
| `princess` | 아군에 일반 퀸이 없으면 퀸 행마, 있으면 대각선 1칸 |
| `hedgehog` | 주변 8칸 도약 + 제한된 역습 횟수 |
| `campfire` | 직교 방향 1칸의 비잡기 이동. 인접 아군을 보호하는 영역 효과를 가진다. |
| `magicGirl` | 평상에는 주변 8칸 도약. 각성 턴에는 퀸+나이트 행마 |
| `trickster` | 현재 `tricksterMoveType`에 저장된 다른 기물의 행마를 사용 |
| `grasshopper` | 선상의 기물 하나를 넘어 그 뒤로 이동/잡기 |
| `cannon` | 이동은 룩처럼 하되, 잡을 때는 중간 기물을 포대로 삼는 대포 행마 |
| `merchant` | 자원(`gold`)을 소모해 적 기물을 구매하는 특수 행동. 현재 밸런스에서 왕 역할일 수 있다. |
| `shotgunKing` | 킹의 1칸 이동 + 탄약을 쓰는 방사/저격 + 재장전 행동 |
| `wizard` | 킹 범위의 비잡기 이동 + 별도 `wizardSpell` 행동 |
| `colossus` | 2×2 발판, HP, 영역 공격을 가진 다칸 기물 |
| `bigRook`, `bigBishop` | 2×2 발판을 쓰는 다칸 기물. 이동·잡기·장애물 판정은 발판 전체를 기준으로 한다. |
| `wall`, `football`, `blackHole`, `coffin`, `scarecrow` | 일반 기물과 다른 중립·장애물·규칙 객체이며, 이동/잡기 규칙을 개별 판정한다. |

이 표에 없는 기물을 임의로 퀸 또는 킹 행마로 가정하지 말고 `generateMovesForPiece()`와 관련 후처리를 확인한다.

### 다칸 기물

`colossus`, `bigRook`, `bigBishop`는 하나의 기물 객체를 2×2 네 칸에 공유한다.

- 상태의 기준점은 `anchorRow`, `anchorCol`이다.
- 순회할 때 객체 동일성 또는 `id`로 중복을 제거해야 한다.
- 이동 가능 여부, 도착 시 잡기, 포털, 붕괴 칸, 보호 효과는 네 칸 전체를 본다.
- 제거할 때는 발판의 모든 참조를 함께 비워야 한다.

### 상태 이상과 보정

기물의 기본 행마와 별개로 다음 상태가 수 생성과 잡기를 바꾸므로 반드시 `GameState`와 개별 기물 필드에 포함해야 한다.

- 이동 불가: `frozen`, 독 기절, `staked`, 주사위 잠금, 탈진
- 잡기 방어: `shielded`, `protected`, 격려, 캠프파이어 영역, `nullification`
- 이동 변경: 포털, 대칭 이동, 사회주의 폰 행마, 기본 훈련, 프로모션 러시, 로커스트 스웜
- 교환/결속: `substitution`, `relay`, `switcheroo`, `chain`, 양자 대응 칸
- 한 턴 제약: 만용, 억제, 캡처 포화, 추가 이동, 잡기 강제

## 7. 구현자가 지켜야 할 불변조건

- 합법 행동의 **종류, 출발지, 도착지, 대상, 추가 플래그**가 oracle과 같아야 한다.
- 행동 적용 후 `board`, `turn`, `actionsRemaining`, `turnsTaken`, `moveCount`, `enPassant`, 카드 상태가 같아야 한다.
- 왕족 역할, 승패, 무승부, 임시 효과의 만료 시점이 같아야 한다.
- 다칸 기물은 직렬화 후에도 하나의 기물로 취급해야 한다.
- 무작위 대상을 고르는 효과는 결과만 비교하지 말고 RNG/seed 규약을 별도로 정해야 한다.
- 설명 문구가 비슷해도 `id`/`effect`가 다른 카드, 표기 별칭(`camelCase`/`kebab-case`), 구버전 별칭을 무조건 동일하게 취급하면 안 된다.

손으로 테스트 상태를 만들 때는 최소한 `turnsTaken`, `actionsRemaining`, `moveCount`, `castlingCanceled`를 채운다. 이 필드가 빠지면 수 생성과 루트 안전성 판정이 실제 게임과 다르게 동작할 수 있다.

## 8. 사이트와 엔진의 일치 검증

- 사이트 워커와 JS oracle 비교: `infra/tools/site-parity/`
- 사이트 대조 사용법: `infra/tools/site-parity/README.md`
- 알려진 차이와 트라이에지: `infra/tools/site-parity/TRIAGE.md`
- JS oracle 스모크 테스트: `cd infra && node smoke-merged.js`
- Rust 엔진과 JS oracle의 differential test 위치: `tests/differential/`

site-parity 비교 시 주의할 점:

- `locustSwarm`과 같은 `OPENING` 카드는 사이트 워커의 초기 설정 경로에서만 완전히 처리될 수 있다.
- `brutus`, `freeze` 등 무작위 대상을 고르는 효과는 RNG가 동기화되지 않으면 보드 결과가 달라질 수 있다.
- 카드 사용은 턴을 넘기지 않으므로, 반복 국면 키에 보드와 턴만 넣으면 카드 연속 사용을 거짓 반복으로 판정할 수 있다.

## 9. 미확정 항목을 처리하는 법

새 카드나 예외를 발견했을 때 이 문서에 추측을 추가하지 말고 다음을 남긴다.

1. 최소 `GameState`와 행동
2. 사이트의 합법 행동/적용 결과
3. JS oracle의 합법 행동/적용 결과
4. 차이가 있다면 `infra/tools/site-parity/TRIAGE.md`의 분류
5. 수정 후 스모크 테스트와 재현 fixture

새로 확정된 핵심 규칙은 이 문서에 요약하고, 최종 세부 동작은 재현 가능한 테스트로 고정한다.
