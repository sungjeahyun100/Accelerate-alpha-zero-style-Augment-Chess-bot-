## 2. 학습 세팅 (`nnue/train.js`, `nnue-train.yml`의 overrides)

| 항목 | 값 / 의미 |
|---|---|
| 입력 | 5509 = 말 평면 40x128 + 카드 184x2 + 특징 21 |
| 구조 | wide & deep, deep 유닛 기본 16 (`ablateDeepUnits`, 8도 시험) |
| 라벨 | `(1-w) * 승패 + w * tanh(검색점수/400)` |
| 기본 검색 비중 w (`ablateBlend`) | 0.15 (실험: 0.3~1.0) |
| 깊이별 비중 (`blendByDepth=1`) | 깊이 1,2,3,>=4 -> 0.25, 0.45, 0.65, 0.8 (`blendDepthMap`) |
| 잔차 (`residual=1`) | 라벨 = tanh((검색점수 - evalBefore) / `residScale`); 검색 점수 없는 국면은 0 |
| 잔차 계수 | 150 / 300 / 600 (사용 시 `@hybrid<계수>`) |
| 종료 시점 가중 | 게임 끝까지 남은 수 `pliesFromEnd` 기준 0.98^n 감쇠 |
| 웜스타트 스케일 | 0.001 (`ablateWarmStart`) |
| 오버샘플 | 1.5 (`ablateOversample`) |
| 저장 | `save_model=<이름>` -> 데이터 브랜치 `models/<이름>.json` |

## 3. 출력 매핑 (대전 사양 `<모델>@<맵>`)

- `atanh<K>`: K * atanh(출력), 학습 압축 tanh(점수/400)의 역, 보통 `atanh400`
- `hybrid<K>`: 수제 평가 + K * 출력 (잔차 모델용)
- `lin<K>`: K * 출력, 기본(맵 없음)은 x100(`SCORE_SCALE`)

## 4. 대전 세팅 (`match.yml`, `tools/lab/lab.js`)

- 색 교환 짝(같은 시드에서 색만 바꿈), 4샤드, 총 게임 = 4 x pairs_per_shard x 2
- 기본: `ms=300`, `depth=3`; 실험실 기본 후보 대전은 `pairs_per_shard=12`, `handicap=1`
- `handicap=N`: 시드로 고른 한쪽에서 비퀸 말 N개 제거(짝은 같은 쪽이 손해라 공정). 무승부: 핸디캡 0 약 57%, 1 약 41~45%, 2 약 39%
- `seed_offset`: 짝 번호에 더해 독립 재실행. `params_a/b`: 검색 파라미터 (`nullMoveMinDepth`=3, `nullMoveReduction`=2, `lmrMinDepth`=3, `lmrMoveThreshold`=4, `quiescenceMaxPlies`=6이 기본)
- 판정(`verdict.json`): win = 95% 구간(Wilson) 하한 > 50%, lose = 상한 < 50%, 그 외 unproven
- 구분 가능한 차이(80% 검정력): 결정 45판 약 +-21p, 결정 100판 약 +-14p, +-5p에는 약 784판

## 8. 발견 기록 (PLAN.md/TODO.md에서 옮김)

### 2026-09-19
- 2라운드 검증(결정 3,159국면, 오차 약 +-1p) 정확도: Squall 기준(blend 0.15) 67.1%, 웜스타트 없음 67.2%, blend 0.3/0.5/0.7/0.8/0.9/1.0 = 69.1/69.2/71.1/70.6(3회 69.5~70.8)/69.8/67.8, deep 유닛 4/8/8+blend0.5/8+blend0.8 = 67.4/68.7/68.9/69.5. 새 엔진 특징으로 재인코딩한 blend 0.8은 70.6%로 같아서 9/19 규칙 변경이 재학습을 강제하지 않음.
- 검색 점수 비중을 올리면 정확도는 +2~4p 오르지만 실전에서는 blend 0.8이 Squall보다 낫지 않았음(42게임: 5승 9패 27무 1미완) -> 정확도가 곧 강도는 아님.
- 클라우드 대전(깊이 3, 300ms, 결정된 게임만, 전부 오차 범위): Tornado 대 Squall 13-17, Typhoon 대 Squall 20-15, 수제 평가 대 Squall 19-15. 깊이 2 대 4(수제, 1500ms) 6-8.
- 무승부가 지배적이라 결정된 게임으로만 판단하고, 10판 미만은 신뢰하지 않는다.
- 평가 약 3.4배, 검색 약 1.5배 개선(출력 동일, `tools/perf`).
- 학습된 망은 말 손익에 거의 반응하지 않음(시작 국면에서 퀸 하나 없을 때 Squall 출력 -0.011 대 정상 +0.078, 수제 평가는 -1284). 라벨이 대부분 무승부라 출력이 0 근처에 몰림.
- 검색 점수 -> 승률 보정(`tools/review-calibration`): 깊은 검색일수록 예측력이 높음(k 전체 3450, 깊이 4~5에서 약 2200). 리뷰 임계값은 이미 손실 1/2.5/5/10% 근처라 값은 적절, 부족한 것은 맥락과 깊이 기반 신뢰도.

### 2026-09-20
- **속도**: 누계 약 2.2배(이전 엔진 대비, 카드 국면 포함 16국면에서 고른 수/점수/노드/컷오프 동일). 구성: 루트 즉시 패배 검사 필터(1.5~1.6배), 위험 캐시와 공격 메모(1.16배), 말 순회 최적화(1.08배), 조용한 수 탐색 정렬 최적화. 노드 수가 한 번 다르게 나온 것은 부하 때문에 시간 기반 검사(`rootSafetyDeadlineTight`)가 달라진 것이었고 한가한 상태에서는 12/12, 16/16 동일. 규칙: 동일성 검증은 컴퓨터가 한가할 때.
- **병목**: 깊이 2 검색이 한 수에 4~12초(노드 400개 남짓, 노드당 약 30ms). 시간의 절반 이상이 루트 안전 검사. 엔진에는 이미 전치표, 널무브, LMR, 킬러가 있음.
- **시도했다 버린 것**: `clonePiece` 키 목록 끌어올리기(이득 0%). 검색 점수를 정답으로 정적 평가 가중치를 회귀(검색 점수에 수마다 붙는 보너스가 섞여 단위가 다름, 현재 가중치 R2 -2.3) -> 승패 기반 튜닝만 가능.
- **시간 연장**(수제, 1500ms): 재대전 22-21, 앞선 결과와 합쳐 40-31(56%)로 유의하지 않음 -> 옵션으로 유지, 미확인.

- **전술 세트**(`nnue/tactics-set.json`, 75문제, 기준 깊이 3 이상): 수제 16.0%, Squall@atanh400 16.0%, blend0.8 17.3%, 잔차 hybrid150 17.3%, hybrid300 18.7% (오차 +-4p) -> 모델을 못 가림.
